# Internationalization (i18n)

Custom lightweight bilingual setup (**no** `next-intl` / i18next).

| Item | Value |
|------|-------|
| Locales | `id` (default), `en` |
| Routing | No URL prefix. Cookie `locale` selects `en` or `id` |
| Preference cookie | `locale` (1 year, `SameSite=Lax`) |
| Detection | cookie → `Accept-Language` (contains `id`) → `id` |

## Request flow

```
Request
  → proxy.ts
      · `/admin` → no locale redirect; cookie gate except `/admin/login`
      · `/en` or `/id` prefix → redirect to the same path without the prefix
      · other paths → set header x-locale from cookie, continue
  → app/layout.tsx (lang={getLocale()})
  → app/(public)/layout.tsx (getDictionary → Providers)
  → page
```

## Dictionaries

```
lib/i18n/dictionaries/
  en/   # source of truth for Dictionary type (WidenValues)
  id/   # same keys; values must satisfy Dictionary
```

Current namespaces: `common`, `home`, `meta`, `errors`, `admin`.

**Usage:**

```ts
// Server Component
const dict = await getDictionary(locale)

// Client Component (inside Providers)
const dict = useDictionary()
```

## Links

```ts
import { ROUTES, localizedPath } from "@/lib/routes"

<Link href={localizedPath(locale, ROUTES.home)} />
// → /
```

Locale switcher: `setLocaleAction` + `router.refresh()` on the same path.

## Adding a key

1. Add to `en/{namespace}.ts`
2. Mirror in `id/{namespace}.ts`
3. If new namespace: export from both `index.ts` files

## Adding a locale

1. Extend `SUPPORTED_LOCALES` in `config.ts`
2. Add `dictionaries/{code}/` matching `en` shape
3. Register loader in `get-dictionary.ts`
4. Confirm `proxy.ts` / switcher use `SUPPORTED_LOCALES`
